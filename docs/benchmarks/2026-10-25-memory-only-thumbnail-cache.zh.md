# 无缩略图磁盘缓存的追加对比

后续决策：已按用户选择将第四组设为默认方案；下文关于默认策略的描述保留测试当时状态。当前实现见[资源管理说明](../performance.md)。

第四组以第三组的冻结代码为基础，只通过 `PVZ_THUMBNAIL_DISK_CACHE=false` 关闭缩略图磁盘读取和写入，不进行无须落盘的 WebP 编码。保留 4 MiB 缩略图内存缓存、原有精灵／地图缓存预算、相同原生宿主和两个窗口引擎。普通构建默认仍启用磁盘缓存。

使用完全相同的测试入口和窗口尺寸，单独实跑两次 Windows Release。操作覆盖卡槽及模仿者选卡、植物／僵尸／物品分类、六类对象外观、其他工具页、十二个预制阵型标签页、37 份旧存档及 363 名阵的完整往返滚动，再静置观察。两组均使用修复后的 WebP 解码实现，本次按③④④③顺序运行；窗口尺寸及驱动哈希一致。

更正：上一轮第三组虽写出了 WebP，但测试快照读取失败、磁盘命中为零。原第三组数据不再作为有效磁盘缓存基线。本报告使用重新测量的数据，并强制检查第三组实际命中磁盘、再次浏览不重新生成。

## 观察

关闭磁盘缓存后，启动阶段的两轮范围重叠，没有明确改善。完整浏览并返回编辑页后，第四组专用工作集中位数低约 21 MiB；但总工作集峰值分别约 349–350 MiB，与第三组约 341–364 MiB 的范围重叠，不能认定峰值稳定下降。

代价是重复渲染：第三组累计生成数保持 381，第四组从 720 增至 1392。第四组不执行无须落盘的 WebP 编码，仍保留有预算的内存缓存；内存图片被淘汰后，需要重新生成。这里关闭的仅是缩略图磁盘缓存，自动保存和用户存档仍正常使用磁盘。

本次只追加测试开关，普通构建默认继续启用磁盘缓存。每组两轮，尚不足以单凭此结果更改默认策略。
