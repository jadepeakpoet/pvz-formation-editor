# 三种资源策略的 Windows Release 内存实测

**更正：**原第三组快照虽然写出了 WebP，但读取缓存失败，实际磁盘命中数为零。原第三组测量及相关结论撤回；本报告已替换为修复解码生命周期后重新运行的两轮数据。第一、第二组已复核，保持原测量值。

同一台机器、Flutter 3.47.8 / Dart 3.13.7、Skia、Windows x64 Release。使用相同原生宿主、自动化入口、窗口尺寸和 DPI，主窗口与共享工具箱／存档侧窗共两个引擎。Logo 统一为原发布版图片，运行时缓存预算一致。

① 使用 v1.0.1 发布标签代码及预生成资源；② 仅取消预裁切图片与掩码；③ 同时移除内置缩略图，按需生成缩略图，以 libwebp 1.6.0、质量 88 写入本地 WebP 缓存。第三组已验证真实读取命中，而非仅检查缓存文件存在。

操作覆盖卡槽与模仿者选卡、植物／僵尸／物品分类、六类对象外观、其他工具页、六种地图的十二个预制阵型标签页，以及 37 份真实旧存档和 363 名阵的完整往返滚动。检测可见缩略图实际显示，使用隔离存档副本。

每组运行两次。第一、第二组沿用原测量；第三组与追加的无磁盘缓存组按③④④③顺序重新测量。每次使用独立空缓存；每 250 ms 采样，阶段值取操作完成后末四秒中位数，再取两轮中位数。不强制 GC 或清空工作集。

## 缓存核验

第三组首次完整往返后的累计生成数：[381, 381]；再次往返后：[381, 381]；最终磁盘命中：[1011, 1011]。再次浏览没有重新生成已落盘预览。

第一、第二组主要使用内置预览，首次及再次完整往返后均只生成 18 张自定义存档预览，本地 PNG 缓存约 2.05 MiB。第三组共写入 381 张 WebP，约 7.58 MiB。压缩文件大小不等于显示时内存占用。

## 结论

本次数据不能支持“移除预生成资源后整体内存大幅下降”的结论。取消预裁切增加了部分操作阶段的峰值；动态生成和磁盘解码也有额外开销。启动占用、完整浏览后的驻留量及峰值应分别评估。

第三组的优势是缩小包内预生成资源，同时能复用本地缩略图；是否关闭磁盘缓存，见[追加对比](2026-10-25-memory-only-thumbnail-cache.zh.md)。该对比使用同一份修复后代码，仅切换磁盘缓存开关。

完整工作集、提交量、两轮范围及缓存计数见同目录 JSON。样本为每组两次，不能将小幅差异视为稳定收益。
