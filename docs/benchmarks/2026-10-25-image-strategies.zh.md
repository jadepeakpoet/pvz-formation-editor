# 三种资源策略的 Windows Release 内存实测

同一台机器、相同 Flutter 3.47.8 / Dart 3.13.7、Skia、同一原生宿主与相同测试入口。每组均为主窗口和一个共享工具箱／存档侧窗，共两个引擎；窗口尺寸与 DPI 相同。Logo 统一为发布版原图，以排除 Logo 优化的干扰。运行时缓存预算保持一致。

三组均从对应代码使用相同自动化入口编译为 Release，原生宿主与引擎文件来自已发布的 1.0.1，用于隔离资源策略的影响。

① 使用 v1.0.1 发布标签的代码和预生成资源；② 仅取消预裁切图片与掩码；③ 同时移除内置缩略图，动态缩略图由 libwebp 1.6.0 以质量 88 在后台编码为 WebP。这里移除的是预生成资源，保留运行时有容量预算的缓存与生成后的本地缓存。

使用 37 份真实旧存档的隔离副本。依次完成十格卡槽及模仿者选卡、植物／僵尸／物品分类、六类对象的外观选择、其他四个工具页、六种场地的十二个预制阵型标签页切换，以及 37 份旧存档和 363 名阵列表的完整往返滚动。检测每项缩略图实际显示。不应用阵型到游戏，不修改游戏状态或用户存档。

每组运行两次，顺序为 ①②③、③②①；每次使用独立空磁盘缓存。每 250 ms 采集进程总工作集、专用工作集和提交量，阶段值取操作完成后的末四秒中位数；下表再取两轮阶段值中位数。静置阶段不强制 GC、不清空工作集。

## 最终本地缓存

- ① 1.0.1：2.05 MiB / 2.05 MiB
- ② 取消预裁切，保留内置缩略图：2.05 MiB / 2.05 MiB
- ③ 无预生成图片，动态 WebP：7.58 MiB / 7.58 MiB

图像在显示时仍需解码；压缩文件大小不等于运行时内存。完整总工作集、提交量、逐阶段数据和波动范围保存在同目录的 2026-10-25-image-strategies.json；测试入口为 tool/asset_memory_benchmark.dart。

其中第三组的 363 张名阵 WebP 缓存为 7,544,712 字节（约 7.20 MiB）；加上 18 张独立旧存档预览，共 381 张约 7.58 MiB。

## 结论

- 第三组启动专用工作集比第一组低约 23 MiB；完整浏览并返回编辑页后，两者相差约 4 MiB，处于两次运行的波动范围内。
- 单独取消预裁切没有降低本次完整操作的内存占用，并提高了总工作集峰值。临时解码整张精灵图再裁切存在额外开销。
- 第三组兼顾包体积和启动占用，但完整操作后的占用接近发布版，峰值仍略高于发布版。不能据此宣称整体内存大幅下降。
- 在本次固定滚动节奏下，三组名阵完整往返都约 17 秒；这不是极限快速滚动帧率测试。
