# 第四种方案的进一步优化

默认使用不读写缩略图磁盘缓存的方案，保留 256×192 分辨率和 4 MiB 内存缓存。自动保存与用户存档保持原有持久化流程。

本次合并同一阵型中的相同外观请求，将图片缓存成员检查改为直接哈希查找。保持原有裁切与缩放路径，图像结果不变。

## 测量

新增两轮完整 Windows Release 实跑。宿主、引擎、原始 Logo、窗口尺寸、37 份旧存档隔离副本、363 名阵均相同。覆盖卡槽选卡、图鉴各分类与外观、十二个预制阵型标签页、所有列表完整往返，以及两次 30 秒静置。每 250 ms 采样，阶段值取末四秒中位数；下表为两轮中位数及范围。未强制 GC 或清空工作集。

## 校验与限制

- 363 名阵三遍完整遍历的独立缩略图检查通过：零磁盘缓存命中、零缓存文件，缓存峰值不超过 4 MiB。
- 489 个原始帧的像素与点击掩码校验通过。保持原有缩放路径。
- 缓存回收、已挂载图片句柄、40 个阵型预览及完整图片重新导出一致性检查通过。
- 每组仅两轮；不能把小幅工作集差异当作稳定收益。固定滚动节奏不能代表极限帧率。

## 结论

本轮启动专用工作集约 136–147 MiB，完整操作后返回编辑页约 241 MiB，没有观察到进一步降低内存的收益。请求合并与直接查找减少了不必要的任务和线性扫描，但不能据此宣称工作集下降。

曾尝试复用完整植物帧生成小图。全流程中实际复用机会很少，且二次缩放引入轻微边缘舍入，最终未保留；缩略图继续使用原有渲染路径和分辨率。

默认策略采用无磁盘缩略图缓存。后续若要减少重复生成，需单独评估缓存命中、生成耗时和驻留内存的取舍，不直接扩大缓存预算。
