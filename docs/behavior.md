# 文档、草稿、存档与编辑历史

以下为用户要求及本应用行为契约（新增设计），不是原网页行为声明。最终实现与测试是否覆盖这些约定，应以 README 的验证记录和功能对照表状态为准。

## 四类数据

| 数据 | 用途 | 谁触发写入 | 是否因继续编辑变化 |
|---|---|---|---|
| 阵型文档 | 地图、对象、占格、图层、外观、显示设置 | 文档命令 | 是 |
| 草稿 | 可恢复的工作副本 | 有效修改后的防抖保存、显式刷新 | 是，独立于正式存档 |
| 我的存档及旧版本 | 用户主动保存的完整快照 | 明确保存/更新 | 否；明确更新时保留旧版本 |
| 撤销/重做 | 本次编辑会话操作历史 | 文档命令 | 会随操作变化，不是正式版本 |

对象选择、当前工具、格子选择、画布缩放与平移属于会话。影响阵型呈现的显示设置属于文档。对象是独立列表，不能用每格单植物字段存储；稳定 ID、行列、占格与图层均参与保存。

## 自动草稿

空白编辑器仅被打开不创建草稿。第一次有效修改才产生独立草稿 ID，多份草稿互不覆盖。修改后在约 500～1000ms 的防抖窗口提交完整文档；离开页面、切换文档、后台和正常关闭时尽力刷新，不能依赖退出回调。

保存成功状态只能在数据库提交成功后显示。失败保留内存文档并显示重试入口。异常终止可能丢失尚未提交的防抖窗口内容，已提示成功的版本应能恢复。草稿记录名称、时间、地图、文档与可选来源存档关联；缩略图可后补，须绑定对应文档版本。

保存按草稿 ID 串行或由版本保护，旧任务不能覆盖新文档。切换前捕获文档和目标 ID，不能让异步回调读取后来切换的会话。删除当前草稿先终止/作废保存任务，再删除数据，迟到任务不得把它复活。用户明确删除以外不自动清理草稿。

## 主动存档

“保存存档”保存完整文档快照、名称、备注和标签。名称不是主键。自动保存仅写草稿，不更新存档。重复保存未修改的同一文档不应不断创建相同快照。

存档默认只读。“继续编辑”创建关联草稿；如果存在关联草稿，提供继续已有草稿或从存档新建副本。之后主动保存时突出“另存为新存档”，更新原存档是明确的另一操作。保存成功后保留工作草稿并记录一致快照，后续修改继续写草稿。

明确更新时，旧快照与新内容必须在同一数据库事务中保存。旧版本只读，恢复旧版本应新建工作草稿。自动保存不产生正式版本。删除草稿不影响存档；删除存档清除来源关联但不破坏草稿完整内容。收藏、复制、搜索、排序及元数据修改应使用稳定存档 ID。

## 编辑命令与历史

所有文档修改统一经过命令机制。一轮连续拖动放置或一次批量操作只生成一条历史记录；撤销/重做会触发草稿保存，但自动保存本身不增加历史。撤销后有新命令则清空重做分支。当前标签未关闭期间保留全部编辑、名称和页面替换的撤销记录；不裁剪为100条，也不按16MiB裁剪。清空、示例替换和换图直接执行，不额外二次确认。撤销栈不跨重启持久化，重启恢复最后成功保存的文档。

快捷键包括 Ctrl/Cmd+Z、重做、保存、Delete/Backspace、Esc；文本输入焦点内不应误执行画布删除等命令。地图变更若存在越界、映射或丢失影响，应预览并让用户选择处理，不应静默删除。

## 文件与快照

应用项目文件须有类型及 schemaVersion，完整保存文档，验证大小、类型、坐标、对象及资源引用。解析完成并通过验证后才替换当前文档，失败不破坏当前工作。原站基本六字段及默认第七字段已用真实样例验证，扩展协议仍未确认；兼容范围见功能对照表，不得将应用 JSON/PVZF1 冒充原站格式。

PNG 只绘制棋盘，排除选框、光标和工具按钮；输出倍率与屏幕缩放无关，并可控制背景透明度。快照对比在创建时复制完整文档，后续修改当前阵型不改变快照。原站镜像面板也声明只读、独立且关闭不保存，已实际创建半比例窗口；其独立性尚未作像素比较。本地采用单个快照对比，不提供原站最多三个多倍率窗口。

## 可靠性验收要点

- 多层及跨格对象往返恢复、连续和批量命令整体撤销重做。
- 草稿离开/重启恢复，草稿修改不污染存档，另存后原快照不变。
- 更新旧版可恢复，删除任一类型不误删另一类型。
- 保存延迟、草稿切换、删除与保存并发时不串档、不回写旧内容、不复活。
- 非法导入不修改文档；项目往返语义一致。
- 数据迁移、数据库写失败、损坏反馈与重试应有针对性验证。
- 原站真实字符串样例、PNG 辅助元素/图层/透明背景需单独验证；未验证的不能计为通过。
