# Windows 原版 1051 游戏接入

2026-10-24：Flutter 3.19.2 / Dart 3.3.0 / VS 2022 / MSVC 19.44 的 Debug 构建通过；真实游戏读取和用户提供的88对象阵型应用通过。

## 参考依据

参考 [PvZ Toolkit 的版本识别、GetLineup、SetLineup、植物及场地调用](https://github.com/lmintlcx/pvztoolkit/blob/master/src/pvz.cpp)和[1051地址表](https://github.com/lmintlcx/pvztoolkit/blob/master/src/data.cpp)。参考源文件位于本机忽略目录 `local-reference/pvztoolkit`，未将 GPL 实现文件纳入产品；Win32 协议、资源生命周期和 x86 指令编码独立实现。

## 之前失败的原因与修正

1. 旧实现要求重新打开 EXE，并比较创建/删除入口与磁盘字节。当前游戏由启动器派生 `popcapgame1.exe`，对自身隐藏 EXE 的独占占用导致 `CreateFileW` 返回32（共享冲突）。这不代表游戏不支持注入。Toolkit 通过运行内存识别版本，不依赖重新打开 EXE。
2. 旧实现没有场地转换或蘑菇睡眠调用，主动拒绝跨场地和白天蘑菇；用户提供的码是泳池，而现场是白天，必然被挡住。
3. 旧实现把“创建目标”的限制也应用到了“删除旧阵型”上，使旧植物的模仿者标记也会阻止覆盖。现在只对新目标的构造做相应限制。

当前识别 PE32 x86、基址 `0x400000`、时间戳 `0x49ecf563`，检查运行内存中的调用入口页已提交、可执行且属于主映像，拒绝明显跳转或无效入口。不再要求读取锁定的磁盘 EXE。

## 行为和范围

- 选卡/战斗场景可以读取；应用限定生存无尽模式11至15，最多512植物。
- 读取植物组成、场地、阳光、睡眠和模仿者标记；可读取墓碑、梯子、钉耙。
- 应用调用游戏删除/创建函数，按底座、主植物、南瓜、咖啡顺序创建；可跨六场地，更新场地背景、行/格地形及推车，离开泳池时清理水波粒子。
- 白天蘑菇通过游戏睡眠函数设置目标状态；土豆雷和阳光菇按Toolkit布阵规则设为成长状态。
- 应用阵型保留游戏现有阳光。阵型码不表达生命、冷却、波次和计时器；不恢复整场游戏。
- 支持模仿者、墓碑、梯子和钉耙的创建与清除；我是僵尸、图像变换、装饰僵尸和图像特效暂不支持，明确拒绝。
- 用户已要求移除游戏阵型历史备份、历史去重和回退按钮。写入前只读取一次临时快照作一致性检查，不保留历史。文件存档备份与资料库历史版本继续保留。

## 调用和失败处理

Lawn指针 `0x6a9ec0`，Board偏移 `0x768`；场地 `Board+0x554c`，阳光 `Board+0x5560`。创建植物 `0x40d120`，EAX为行，栈为Board/列/类型/模仿目标；删除植物 `0x4679b0`；睡眠函数 `0x45e860`，EAX为植物地址、栈为bool；背景函数 `0x40a160`，ESI为Board。

原生在实际执行前重新识别进程与模式，暂时把主循环字节 `0x552014` 从DB改为FE，等待两帧后复核Board及读取快照；组成/场地/阳光变化则拒绝。远程线程保留寄存器并以ret4返回。完成后重读并核对目标组成、场地、阳光，再恢复并检查主循环。

超时不释放仍在执行的代码，也不提前恢复主循环。后台等待完成再恢复并释放资源；未确认主循环恢复则阻止后续写入。该流程不宣称跨进程事务原子性。

通道 `pvz_formation_editor/game` 提供 `listGames`、`readFormation {pid}`、`applyFormation {pid,target,expectedBefore}`、`listSaveFiles`、`saveFolders`。`expectedBefore`是当前一致性检查快照。
